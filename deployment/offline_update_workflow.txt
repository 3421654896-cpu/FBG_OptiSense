离线客户更新发布流程

2026-10-10 起客户更新唯一入口为开发者发送的完整签名更新包及独立更新助手。
主软件隐藏固件更新/客户端更新页，停用自动 GitHub 检查和更新气泡。
USB 引导程序和升级协议保留；不得因入口隐藏而删除设备升级能力。

客户只需要 Windows 10/11 64 位，不需要 Python。
首次发 Setup.exe；后续发完整更新目录或其压缩包，客户分别点击软件更新和 USB 固件更新。
默认客户端安装路径为 %LOCALAPPDATA%\Programs\FBG OptiSense Studio。

开发者操作
1. 完成新客户端/固件验证，更新对应版本号并构建完整冻结客户端目录。
2. 使用 Python/prepare_offline_release.py 生成客户端 ZIP、固件副本及签名清单。
   --key 指向仓库 .release-signing/offline_ed25519.key（私钥）
   --client-dir 指向完整 app_universal_build 目录
   --output 指向新的发布目录（脚本拒绝覆盖已有发布目录）
   --version 指定客户端版本
   --firmware 指向已实机验收的 .fbgfw
   --device-serial 指定允许刷写的完整 USB 序列号，可重复给出
3. 把冻结的 OptiSense_Update.exe 放入同一个发布目录；它内置公钥，只接受此签名者的清单。
4. 完整目录打包并发送。可仅给选定客户发送，也可发送给所有客户。
5. 在隔离安装目录验证升级、记录保留和回滚，实机验证身份与重启后固件版本，再发给客户。

保护私钥
.release-signing 已被 Git 忽略。私钥不得放进客户端、更新助手、安装包、压缩包或 GitHub。
需要独立离线加密备份私钥；不要重新生成替换，否则旧更新助手不再接受新签名。
源码可按发布者决定提交到开发协作仓库；签名私钥、现场凭据、客户运行记录和私有板卡备份始终不得上传。
公开密钥存放于 Python/update_public_key.py。

范围
离线签名校验不是在线授权服务，也不是自动推送系统。
UID 列表是刷写对象隔离，不阻止有人把客户端更新包转发给别人。
固件 USB 更新要求设备先已具备兼容引导程序；不能替代初次烧录。
若客户首次安装目录不存在，请先用 Setup.exe 安装，不要把更新助手当首次安装器。
候选固件未经对应设备验收不能自动提升到客户的一键更新目录。

自动化软件更新/验收入口
OptiSense_Update.exe 支持 --apply-client-update，必须同时明确给出 --install-dir 与新的 --result-file。
该入口与界面按钮共用 UpdateWorker，同样验证签名、文件 SHA-256、正在运行的客户端和目标目录。
结果文件含更新状态、旧目录备份路径与错误；已有结果文件拒绝覆盖。
此入口只更新客户端，不发送固件命令；客户日常操作仍是双击后使用两个独立按钮。
