# 三号机USB更新、网络OTA删除与DAC轮询验证

2026-10-11，用户确认三号机客户端已关闭并授权烧录。原生USB身份为COM18 / 207933893232。最终实际运行v1.0.118 Beta，USB更新后版本与新启动标识均已确认。

## 实际保留与删除

- 活动固件删除LAN/WAN更新入口、WAN PING/ABORT与整包HMAC专用分支、网络更新响应队列和网络更新重启/超时流程。`FBG_FEATURE_NETWORK_OTA=1`直接编译报错，不能意外恢复。
- USB更新仍由物理CDC ISR收帧，主循环执行；共享命令引擎改为私有函数且仅允许transport=3。保留USB身份绑定、分块/整包CRC、关光、暂存区、配置保护、引导安装以及回复发送完成后复位。
- LAN RAW数据、握手/租约/重连/批量压缩、USB/LAN共用密集/手指采集、145 mA电流限幅、统一40°C温控及安全停止ACK保留。
- 主软件的两个更新页继续隐藏；历史电脑端网络开发工具未批量删除，不能向新版固件执行网络更新。没有重新打包客户软件或更新客户目录。

删除前源码及原实际v1.0.115包存于`backups/network_ota_removal_20261011`。这不是不可恢复删除，不改板卡的已存校准参数或Wi-Fi配置。

## DAC候选对照

新寄存器轮询仅为开发候选：400 kHz、原五路顺序、各路独立START/STOP、MSB/LSB、ACK与BTF检查、电流/温控保护不变。没有合并GAIN/SOA，没有跳过相同DAC码，没有缩短逐点或跨峰等待。

v117在每路STOP后等待空闲；v119将中间STOP收尾与下一路软件准备重叠，下一START仍须确认空闲，最后一路确认STOP结束。故障优先于就绪标志，仲裁丢失不发送STOP；错误先关光，恢复后重试成功也不能把失败行当成成功并重新开光。实际ARM代码在MMIO仿真中验证NACK、总线错误、仲裁丢失、各阶段超时、计数器回绕和锁/IRQ/DMA拒绝。

同一三号机、63点、CH0/5 kΩ、单次ADC、每点850 µs；所有DAC码均为0。每版3次64帧，前16帧预热，使用板端时间戳拆分预算。原始帧和wire日志均保存，不覆盖历史记录。

| 固件 | 帧率范围 | DAC及点间处理 / 帧 | 处理结果 |
| --- | --- | --- | --- |
| v115原HAL基线 | 11.304～11.312 Hz | 32.370～32.425 ms | 原基线 |
| v117轮询候选 | 11.212～11.214 Hz | 33.124～33.125 ms | 未提速，退出使用 |
| v119轮询候选 | 11.285～11.289 Hz | 32.535～32.539 ms | 未提速，退出使用 |
| v118 USB-only原HAL | 11.306～11.313 Hz | 32.338～32.396 ms | 最终安装版本 |

四组纯等待均为53.55 ms/帧，不把移除等待、不同ADC次数或绘图刷新当作DAC提速。v118与原基线差异很小，不宣称本轮提高帧率。400 kHz下每路地址+寄存器+两字节数据共36个SCL周期，五路纯线速预算约450 µs/点；额外安全/温度/协议处理尚存在，不能将该理论值当成实测。

## 最终验收

- v118通过USB安装，用时约9.3秒（其中载荷传输约2.1秒）；之后的USB查询仍可正常执行，兼容更新引导程序仍有效。
- 192帧63点零电流复测完整，无I2C/SPI错误，温度约30.45～30.49°C，遥测无故障、传感器年龄最大420 ms；每次独立确认停采和关光。
- 单值零电流ACK、100帧ADC监视及温度、手动零电流命令、旧模式/ARM拒绝、2001点密集采集（3000 µs）、旧45点32帧（850 µs）通过，最终停采/关光回执成功。旧45点双ADC约15.30 Hz，与63点单ADC不能混为同一测速条件。
- 144项固件/USB/LAN/安全/预算离线回归通过，构建0错误0警告；包含真实ARM驱动故障注入测试。可选Unicorn依赖仅安装在临时验证目录，未加入客户依赖。
- BW20状态为Wi-Fi未连接、UART收包数0、退避状态；192.168.4.62的LAN连接未建立。因此本轮仅确认LAN源码/协议回归保留，没有LAN实机吞吐验收，也没有带光精度验收。未复位或重配无线模块。

本轮未改用户保存的等待表、采谱默认、校准表、客户端界面、安装包、客户更新清单或GitHub远程。
